# 16 · 三角色权限方案初版（Twenty 原生 RBAC，2026-08-10）

> 基于 Twenty 2.17 **原生角色系统**（core.role + objectPermission + rowLevelPermissionPredicate + permissionFlag）设计三个身份。取代之前注入的 conv.user_roles。
>
> 三身份：**后台管理员 / 销售主管 / 销售**。待与需求方对齐后再落地建角色。

---

## 1. 权限维度（Twenty 原生真实可配项）

- **记录级总开关**（role 表）：查看 / 编辑 / 软删除 / 彻底销毁「所有对象记录」
- **设置项**（14 项）：数据模型、角色、安全、工作区、成员、API/Webhooks、AI、工作流、布局、账单、应用…
- **工具项**：导入CSV、导出CSV、下载文件、上传文件、发邮件、HTTP请求…
- **对象级**（objectPermission）：可对单个对象（线索/客户/项目/会话…）单独放开或收紧
- **行级**（rowLevelPermissionPredicate）：控制「能看到哪些行」——这是「看团队 / 看自己」的核心

---

## 2. 三角色权限矩阵（初稿）

| 维度 | 后台管理员 | 销售主管 | 销售 |
|---|---|---|---|
| 查看所有记录 | ✅ 全部 | ✅ 全部（暂不设团队边界，见 Q1） | ⚠️ 仅自己（行级过滤） |
| 编辑所有记录 | ✅ | ✅ | ⚠️ 仅自己 |
| 软删除记录 | ✅ | ✅ | ❌ |
| 彻底销毁记录 | ✅ | ❌ | ❌ |
| 系统设置（数据模型/角色/安全/成员等） | ✅ 全部 | ❌ | ❌ |
| 工具·导入CSV | ✅ | ✅ | ❌（防批量导入脏数据） |
| 工具·导出CSV / 下载 | ✅ | ✅ | ⚠️ 见 Q3（防导出客户资料） |
| 工具·发邮件/上传 | ✅ | ✅ | ✅ |
| 行级可见范围 | 无限制 | 无限制（全部）/ 或团队 | 仅「负责人=自己 或 参与者含自己」 |

---

## 3. 行级规则（核心，销售身份用）

**销售**只能看到「属于自己」的记录，判定字段 = 记录的**负责人**：
- 线索 `opportunity.ownerId` = 当前用户
- 项目 `xiangMu.fuZeRen` = 当前用户
- 客户 `person.??`（当前 person 没有负责人字段，需补）
- 会话：owner_id = 当前用户（已有）

> ⚠️ **强依赖字段统一**：行级规则要 key 在一个**三维度统一的「负责人」字段**上。当前商机叫 `owner`、项目叫 `fuZeRen`、客户没有——必须先把「负责人」在三个维度统一（见 docs/15 决策 #3），行级权限才能一致生效。

**销售主管**初版建议：先不设团队边界 = 看全部记录（跟管理员一样看记录，但没有系统设置权）。等有了「团队/上级」归属字段，再收成「只看本团队销售负责的记录」。

---

## 4. 落地方式

- **后台管理员**：可直接沿用内置 Admin 角色（不可改名），或新建自定义「后台管理员」角色替代。
- **销售主管 / 销售**：新建自定义角色，按上表配开关 + 行级规则。
- 建角色走 Twenty 原生「设置 → 角色」（会正确初始化 5 张权限表），不手写 SQL。
- 重置密码功能迁到原生成员页（截图已见橙色「重置密码」按钮），注入的旧「权限」页退役。
