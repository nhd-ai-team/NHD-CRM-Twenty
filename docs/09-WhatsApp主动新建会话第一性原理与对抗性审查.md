# WhatsApp 主动新建会话：第一性原理与对抗性审查

## 1. 第一性原理

用户真正需要的不是“新增一行会话”，而是让一名已登录销售通过当前绑定的 WhatsApp 账号，可靠地向一个明确客户发送首条消息，并让后续沟通在 CRM 中连续、可追溯。

因此最小完整链路必须同时满足：确认操作者身份、确认渠道在线、确认目标号码有效、发送前二次确认、成功外发、会话与消息落库、已有会话复用、失败原因明确。缺少任一环节，都只能算前端入口而不是可交付能力。

## 2. 当前设计结论

| 约束 | 实现 |
| --- | --- |
| 操作者可信 | 校验 Twenty 登录令牌，并确认令牌用户对应当前工作区成员 |
| 目标明确 | 只接受 7-15 位国际号码；支持 `+`、空格、括号和 `00` 国际前缀归一化 |
| 目标可达 | 发送前调用 WAHA `contacts/check-exists`，未注册号码不发送 |
| 防止误发 | UI 展示目标号码和首条消息，用户二次确认后才发送 |
| 防止重复会话 | 数据库以 `(channel, external_chat_id)` 唯一；同号码复用已有会话 |
| 防止重复发送 | 每次提交生成 UUID 幂等键；相同请求只允许一次外发 |
| 会话责任明确 | 主动发送后状态设为 `takeover`，记录当前 Twenty 用户为 `agent_id` |
| 数据连续 | 首条销售消息写入 `conv.messages`，并更新会话最后消息和时间 |

## 3. 对抗性审查

### 已处理风险

1. **号码格式伪装**：去除展示字符后按国际号码长度校验，避免不同格式绕过重复检测。
2. **未注册号码**：WAHA 校验失败即停止，不创建空会话。
3. **向自己发消息**：目标号码与当前绑定账号一致时阻断。
4. **双击和网络重试**：幂等键唯一；处理中、已发送、已完成分别处理。
5. **先发送后落库失败**：状态在渠道发送成功后立即标记为 `sent`；重试不会再次外发。
6. **已有会话重复建档**：数据库唯一约束和 upsert 双重保证复用。
7. **跨站伪造请求**：同源检查之外增加 Twenty 令牌和工作区成员验证。
8. **伪造用户头**：`X-Twenty-User-Id` 必须与登录令牌中的用户一致。
9. **超长消息**：首条消息限制为 4096 字符。
10. **发送成功但界面刷新失败**：发送成功与列表刷新分离；刷新失败不会向用户误报“发送失败”。
11. **快速双击产生两个请求**：幂等键在弹窗打开时生成并在整个提交周期固定，不随每次点击变化。

### 保留风险与后续要求

1. **WhatsApp 个人号风控**：技术上能主动发送不等于平台允许批量获客。v1.0 仅支持人工逐条发送，不做批量、定时和自动外呼。
2. **渠道发送成功但 CRM 持久化失败**：系统优先保证不重复打扰客户，并保留 `sent` 幂等记录；后续应增加后台补偿任务自动完成归档。
3. **销售权限颗粒度**：当前验证“已登录工作区成员”，尚未增加独立的“允许主动外发”角色权限。正式扩大用户范围前应增加权限开关。
4. **发送频率**：当前没有基于用户/号码的持久化限频。正式运营前建议增加每用户小时上限、同号码冷却时间和异常告警。
5. **合规与客户同意**：CRM 无法自动证明客户授权。业务制度需明确允许联系的客户来源和退订处理方式。

## 4. 发布判断

当前实现满足人工、单条、低频主动联系的 v1.0 场景。以下任一能力加入前必须重新审查：批量发送、AI 自动主动联系、营销模板群发、定时发送、多 WhatsApp 账号路由。
