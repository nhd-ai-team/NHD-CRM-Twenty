# 06 · 未来规划（官网 AI 客服对接）

最后更新：2026-08-24
状态：✅ 1.0 已按自研对话中间层方案落地；本文保留早期规划背景，并同步当前实现口径

---

## 目标

公司官网正在重建。计划让官网的 **AI 客服**与 Twenty CRM 打通，实现：

1. **自动获客**：访客跟 AI 客服聊天、留下联系方式后，自动在 CRM 建客户/公司/商机
2. **人工接管**：AI 答不上来的问题，转人工实时对话

---

## 整体架构

```
官网访客 ─→ 官网 Widget / AI 客服服务 ─→ CRM middleware ─→ conv 会话库 + Twenty 业务库
                                      │
                                      └─→ CRM 对话工作台人工接管 / 回复 / 更新线索
```

**三个 AI/角色，别混淆：**

| 角色 | 在哪 | 干什么 | 看得到官网对话 |
|---|---|---|---|
| AI 客服的 LLM | 官网 AI 客服服务 | 受策略控制地生成官网回复 / 兜底话术 | ✅ |
| 中间层 | CRM middleware | 消息入库、字段映射、去重、渠道转发、AI 调用编排 | — |
| Twenty 的 AI | CRM 里 | 分析 CRM 已有数据 | ❌ |

---

## 需求一：访客留资 → 自动建客户（可行）

**流程：**
1. AI 客服的 LLM 一边对话，一边判断"要不要写入 CRM"（有没有有效联系方式、是不是真实意向）
2. 判断为是 → LLM 从对话抽取结构化信息（姓名/邮箱/电话/公司/国家/咨询产品/意向度）
3. 中间层接收，做字段映射
4. 中间层带 API Key 调 Twenty 接口写入客户/公司/商机
5. 客户几秒内出现在 CRM

**能自动获取的数据**：姓名、邮箱、电话、公司、国家、咨询产品、需求描述、意向度、来源、对话记录

**需人工后续补的**：客户真实性核实、商机金额/成交概率、客户背景调研、去重合并、报价合同附件

---

## 需求二：在 CRM 里跟访客实时聊天（当前通过自研工作台实现）

**重要现实**：Twenty 原生仍然不是在线客服系统，但当前项目已经通过自研 `chat-ui` + `middleware` + 注入导航的方式，在 CRM 内提供「对话工作台」。

当前实现：

- 官网客服、WhatsApp、Email 会话进入 `conv` schema。
- 销售在 CRM「对话工作台」中查看、接管、回复、发送附件、更新线索。
- 官网会话同步展示公网 IP 推断国家 / 地区 / 城市 / 时区、访问页、来源页和 UTM 参数。
- WhatsApp 由 WAHA 连接；Facebook / Instagram 一期暂不接入。
- Chatwoot 仅保留为历史评估方案，当前 1.0 不作为消息中心。

## 需要开放的接口清单

```
官网/AI客服端：
  - 出站 Webhook（把客户数据推出来）        ← 必须
  - 实时消息 WebSocket（如要人工接管）      ← 看需求

中间层：
  - 一个接收地址（收官网推来的数据）        ← 必须
  - 调 Twenty API 的逻辑                    ← 必须
  - 保管 API Key（不能放官网前端）          ← 安全要求

Twenty 端：
  - REST/GraphQL API + API Key             ← 现成
  - Webhook（如要 CRM 反向通知）            ← 现成
  - 公网地址                                ← 需先部署到公网

实时聊天/人工接管：
  - CRM middleware + chat-ui                 ← 当前已实现
  - WAHA                                     ← WhatsApp 个人号连接
  - 官网 AI 客服服务                          ← 官网 Widget / AI 回复 / 兜底
```

---

## ⚠️ 前置条件（做这个之前必须先解决）

**CRM 必须有公网 HTTPS 访问入口，并保证反向代理传递真实访客 IP。**
当前官网来源信息依赖服务端链路透传 `CF-Connecting-IP` / `X-Forwarded-For` / `X-Real-IP` 或 `X-Original-Client-IP`。如果只传 Docker 内网 IP，CRM 只能看到 `172.18.x.x`，无法判断真实国家、城市和时区。

## 分阶段落地建议

| 阶段 | 做什么 | 价值 |
|---|---|---|
| 阶段1 | 官网客服 / WhatsApp / Email 会话进 CRM，对话工作台、线索沉淀、AI 兜底、附件、来源信息展示 | 已进入稳定测试 |
| 阶段2 | 去重合并、权限、线索转客户 / 转项目、三维度同步、沟通状态审计 | 持续优化 |
| 阶段3 | Facebook / Instagram、营销自动化、客户数据分析、复购经营 | 后续评估 |

## 价值与风险（决策参考）

**能解决的痛点**：询盘漏接、客户信息散落、海外时差错过商机、不知道谁值得优先跟、销售离职带走客户、官网获客效果看不清。

**优点**：获客自动化、24 小时不打烊（适合外贸跨时区）、客户数据资产化、响应快。

**风险**：AI 抓取不完美需人工抽检、脏数据需去重、过度依赖 AI 伤体验（人工通道必须畅通）、维护成本、隐私合规（GDPR）、初期投入。

**判断**：值得做，但分阶段。核心价值是"让官网从展示页变成 24 小时获客机器，每个客户沉淀成可经营资产"。最该警惕：别为全自动牺牲体验，AI 做接待+初筛，真人做深度跟进。
