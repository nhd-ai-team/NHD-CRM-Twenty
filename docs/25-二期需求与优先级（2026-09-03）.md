### AI 客服当前状态

知识库尚未正式搭建，配置为**强制全兜底**：`aiEnabled=true` + `aiBackendAvailable=true` + `knowledgeMinScore=100`（检索永不命中 → 全部走离线兜底话术）。

## 二、二期需求清单（9 条）

会议中提出、已确认口径的需求。**Bug 类单独记录在第四节，不计入本清单。**

### 23 · 客户姓名 → 对话名称同步
- **痛点**：左侧对话名是系统生成的（如"网站访客 1c423e"），右侧表单填了真实客户姓名后左边不变，列表里认不出人
- **要什么**：右侧表单填写客户姓名后，左侧对话名称自动同步
- **边界**：手动改对话名称的能力保留；单向同步（表单 → 对话名），不是双向

### 24 · 销售在岗但未回复 → AI 兜底接管 ✅ 已实现
- **痛点**："人工在线，但没有识别到这个消息"，客户干等（"客户留存 30 秒就走了"）
- **要什么**：在岗状态下，客户消息 **1 分钟**内无人工回复 → AI 兜底回复该条
- **边界**：与既有"120 分钟闲置释放接管"是两回事；时间定为 1 分钟（30 秒被认为太短）
- **待补**：会上提到但未定——是否给销售倒计时提示

### 25 · 同一访客多条线索关联提示
- **痛点**：同一人换 tab / 关了再开 / 换浏览器 / 换设备 / 挂 VPN，每次生成新线索（按 session 区分）。风险是"未来 sales 多了，好几个人同时对接同一个项目"
- **要什么**：**不做自动合并，只做"可能关联"提示**——历史记录里把同一 IP 的对话并排展示，上方标注"归属同一 IP，可能有关联"，由销售自行判断
- **已排除方案**：按 Google 账号识别（拿不到）、穷举 IP 组合
- ⚠️ **表中标题"官网表单去重"需修正**：会议讨论的是官网**客服会话**产生的线索，且不是"去重"而是"提示关联"

### 26 · 每条消息上方显示发送人 ✅ 已完成
- 人工消息显示回复人姓名；AI 消息保持"AI 自动回复"；客户消息不显示（确认不加）；不加主管标识（确认不加）

### 29 · 邮箱界面分清收发
- **痛点**："全部接在一块儿，像一个 markdown 文本框""我得非常清楚地知道这是什么情况、谁发过来的"
- **要什么**：一眼分辨每封是收还是发，做得更像邮件客户端。**参考对象：网易邮箱大师**

### 30 · 邮箱客户名称从抄送人中选择
- **痛点**：只能识别"发给我的那个人"，但一封邮件常抄送工程师、采购等多人，真正的对接人未必是发件人；甚至出现"识别到我自己"
- **要什么**：识别出邮件相关人后，在右侧客户表单提供**下拉让销售自选**
- **边界**：候选人涵盖**过往所有邮件**的抄送人，不只最新一封

### 31 · 邮箱分类（建议拆成三条独立需求）
跨了三个优先级档位，工作量差异大，合并会互相拖累：

| 子项 | 内容 | KANO |
|---|---|---|
| **31①** | 区分 收件 / 发件 / 垃圾。标记为广告/垃圾的不进 CRM 正式客户邮件归档 | 必备 |
| **31②** | 对接网易邮箱大师，同步已有的分类与标记，避免重复劳动 | 兴奋 |
| **31③** | 邮箱两级视图：①「全部邮件池」（可搜索）②「已录入线索」（在某封邮件右侧填了客户信息则自动进入）。销售两个日常动作：从全部池筛出值得跟进的填客户信息；到线索列表看重点客户新邮件 | 期望 |

### 32 · 新消息推送钉钉
- **形式**：钉钉**工作通知**（单人消息），**明确不发群**
- **推送规则**：

| 场景 | 通知对象 |
|---|---|
| 新客户第一次询盘 | 所有人 |
| 已归属某销售的客户 | 只通知该销售 |
| 会话已被接管 | 只通知接管人 |

- **注意**：会上先说"没在线就不通知"，后被推翻——**不在线也要推**（"你们也需要知道系统上有消息"）

### 33 · 客户列表排序固定
- **痛点**：转客户后在客户列表里找不到新记录，"不在第一条，直接跑到下面去了"
- **要什么**：客户列表默认按时间排序，且**在后台设为默认**，不是让每个销售自建视图
- ⚠️ **表中记录为"线索视图"，会议讨论的是客户列表**，需确认是只改客户还是两个都改
- **调查结论见第三节**

## 三、KANO 优先级

| 类型 | 需求 | 判断依据 |
|---|---|---|
| **必备** | 33 排序 | 转完客户找不到人，列表基础可用性 |
| **必备** | 26 显示发送人 ✅ | 多人协作不知道谁回的 |
| **必备** | 23 姓名同步 | 既然让填客户姓名，列表就该显示 |

| **必备** | 31① 垃圾邮件分类 | 垃圾邮件混进客户归档是数据污染 |
| **期望** | 32 钉钉推送 | 现在"只能盯着这个地方"，漏消息直接丢线索 |
| **期望** | 31③ 邮箱两级视图 | 省掉每天翻找的操作 |
| **期望** | 24 AI 兜底 ✅ | 客户"留存 30 秒就走"，响应速度的保险 |
| **期望** | 30 抄送人选客户 | 录入准确率 |
| **兴奋** | 25 同 IP 关联提示 | 现在 3 个销售不痛，有了是超预期 |
| **兴奋** | 31② 对接网易邮箱大师 | 没人指望能打通，做到省一大截重复劳动 |

### 建议排期

- **第一批（必备，补齐及格线）**：`33` → `23` → `29` → `31①`（26 已完成）
- **第二批（期望，拉满意度）**：`32` → `31③` → `30`（24 已完成）
- **第三批（兴奋，看余力）**：`25` → `31②`

### 两个提醒

1. **24 的价值依赖 AI 知识库**。当前是强制全兜底状态，此时"1 分钟 AI 接管"只是让兜底话术早点出现，价值打折。知识库就绪后才能体现完整价值。
2. **25 是会衰减的兴奋型**。现在 3 个销售撞单概率低所以不痛；销售扩到 8-10 人时会变成必备型，不要永远压着。

## 四、需求 33 排序问题的调查结论

**现象**：界面上设置视图排序后，刷新即重置。

**已查明的事实**：

1. `core."viewSort"` 表**从来没有过任何一行**（含软删），说明排序从未成功持久化——不是被覆盖，是保存就没成功
2. 客户、线索的默认列表用的是 Twenty **标准视图**（`isCustom = false`，名称仍是模板占位符 `All {objectLabelPlural}`）
3. 所有标准视图的 `updatedAt` 均为同一时间戳 `2026-08-31 08:15:22`，说明被元数据同步**批量重写过**；自建视图（`线索`、`超出权限`，`isCustom = true`）保留各自时间戳未被动

**推断（未验证）**：标准视图会被元数据同步重新生成，挂其上的排序配置一并被冲掉。

**两个候选方案**：

| | 做法 | 优点 | 风险 |
|---|---|---|---|
| A | 直接向标准视图写入 `viewSort` 行 | 最快 | 若推断成立，下次清元数据缓存 + 重启即失效；而改字段就需清缓存，会反复失效 |
| B | 建自定义视图（带排序）并设为默认 | 自定义视图不参与标准视图重新生成，可长期稳定 | 多一个视图，用户需习惯从该视图进入 |

**建议**：先按 A 写入一行，再主动触发一次「清元数据缓存 + 重启 server」验证是否留存。留存则 A 足够；被冲则证实推断，改用 B。

**待确认**：排序字段用 `Last update`（任何编辑都会顶到最前）还是 `Creation date`（仅按转客户时间排，但依赖客户创建时间正确——见第四节 bug）。
