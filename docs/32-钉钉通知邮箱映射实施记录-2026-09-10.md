# 32 · 钉钉通知邮箱映射实施记录

最后更新：2026-09-10

## 1. 映射规则

官网客服消息进入 CRM 后，通知收件人按以下链路解析：

```text
CRM 负责人/协办人/协办人2登录邮箱
  -> DINGTALK_USER_MAP_JSON
  -> 钉钉 UserId
  -> 内部应用工作通知
```

测试阶段使用：

```text
DINGTALK_SALES_USER_EMAILS=lyw632806@gmail.com
DINGTALK_USER_MAP_JSON={"lyw632806@gmail.com":"01310655316821121987"}
```

未分配会话的首条消息使用 `DINGTALK_SALES_USER_EMAILS` 作为默认收件人。`DINGTALK_SALES_USER_IDS` 保留为兼容旧配置的直接钉钉 UserId，不建议作为新的主配置。

## 2. 通知范围

- 主管接管期间：只通知当前接管人。
- 非接管状态且已分配：通知负责人、协办人、协办人2中有映射的成员。
- 未分配：只在首条客户消息时通知默认销售邮箱列表。
- 没有映射的成员不会被误发，后台记录无映射日志。

## 3. 验证要求

1. 用未分配官网会话发送首条消息，确认刘宇文收到工作通知。
2. 给会话分配负责人后发送新消息，确认按负责人邮箱映射发送。
3. 添加协办人或协办人2后发送新消息，确认对应映射收件人也收到。
4. 删除/填写不存在的映射，确认不崩溃、不发送到错误账号。
