## 0. 代码结构与数据模型速览

### 0.1 系统架构

```
官网表单 / WhatsApp 等渠道
        │
        ▼
Cloudflare 隧道（crm.chinanhd.com）
        │
        ▼
portal nginx（twenty-twenty-portal-1 :3000）
        │
        ├─ /api/*（机会/客户/项目等 Twenty 业务）→ Twenty server（:3000 GraphQL）
        └─ /api/conversations/*、/api/whatsapp/*、/api/website/form、
           /api/opportunities/:id/convert-to-* → middleware（:3002）
        │
        ▼
PostgreSQL（twenty-db-1）+ Redis（元数据/缓存）
```

**关键容器**：`twenty-server-1`(GraphQL 引擎)、`twenty-worker-1`(后台任务)、`twenty-twenty-portal-1`(nginx 门户)、`twenty-middleware-1`(Node/Express 业务中间件)、`twenty-db-1`(Postgres)、`twenty-redis-1`(缓存)。

## 1. 两条链路的端到端流程

### 链路 1：官网表单 → 线索 → 转客户 → 转项目

```
官网表单 POST /api/website/form（x-webhook-secret 鉴权）
  └─ normalizeWebsiteFormPayload() 归一化 5 字段
  └─ createOpportunity（GraphQL）
       ├─ 标题 = company || email || phone || '官网表单线索'
       ├─ stage 由 DB 触发器强制 = WEI_CHU_LI_XIANSUO（未处理线索）
       └─ keHuLaiYuan = GUAN_WANG_BIAO_DAN
  └─ 补 leadNo(XS-时间戳) / customerIdentityKey / syncGroupCode
  └─ name → lianXiRenXingMing（官网联系人姓名暂存列，不建 Person）
  └─ company（若有）→ 建/关联 Company
        │
        ▼  [销售在 CRM 手动改 stage：未处理线索 → 线索/有效线索…]
        │
        ▼  [销售填写「客户需求产品」keHuXuQiuChanPin]
        │
转客户 POST /api/opportunities/:id/convert-to-person（需真实 Twenty token）
  ├─ 前置校验：keHuXuQiuChanPin 非空，否则 409 PRODUCT_REQUIRED
  └─ upsertPersonFromOpportunity：按 syncGroupCode/邮箱/电话 去重建 Person
       ├─ Person.name = lianXiRenXingMing || opportunity.name
       ├─ 回填 pointOfContactId + linkedPersonId
       └─ leadNo 同步
        │
        ▼
转项目 POST /api/opportunities/:id/convert-to-project
  ├─ 前置校验：keHuXuQiuChanPin 非空
  ├─ 先 upsert Person（自动补客户关联，保持漏斗完整）
  └─ upsertProjectFromOpportunity：按 sourceOpportunityId 去重建 _xiangMu
       └─ 回填 linkedProjectId + linkedPersonId + leadNo 同步
```

### 链路 2：WhatsApp → 线索 → 更新 → 转客户/项目

```
WAHA webhook POST /api/whatsapp/webhook（带 session）
  └─ persistWhatsAppMessage：按 session 反查 owner，落 conv 三表
  └─ 首条客户入站 → ensureOpportunityForInboundConversation 自动建线索
       ├─ stage = XIANSUO（线索）
       └─ keHuLaiYuan = WHATSAPP
        │
        ▼  [销售在对话工作台右侧「资料」面板填字段]
        │
转为线索 POST /api/conversations/:id/convert-to-lead（需真实 Twenty token）
  ├─ 已自动建线索 → updateOpportunity（isUpdate）；未建 → createOpportunity
  ├─ 补电话/邮箱且 stage 仍为 XIANSUO → 升级 YOUXIAO_XIANSUO（有效线索）
  ├─ name → lianXiRenXingMing；company → 建/关联 Company
  └─ 记 contact.twenty_opportunity_id
        │
        ▼  [更新线索信息：再次 convert-to-lead，或 CRM 界面改字段]
        │    └─ 触发 opportunity-updated webhook → 电话/邮箱单向同步到 Person
        │
        ▼  [填写「客户需求产品」]
        │
转客户 convert-to-person → 转项目 convert-to-project（同链路1）
```

## 3. 链路 1 测试用例（官网表单）

### TC-WF-01 表单提交 → 自动创建「未处理线索」
- **前置**：无
- **步骤**：向 `/api/website/form` POST `{name, phone, email, country, message, company}`
- **预期**：
  1. 返回 201，含 `opportunityId`、`leadNo`（`XS-` 前缀）、`personId=null`
  2. DB 断言：`opportunity.stage = WEI_CHU_LI_XIANSUO`；`keHuLaiYuan = GUAN_WANG_BIAO_DAN`；`lianXiRenXingMing = name`；`pointOfContactId IS NULL`（未建客户）；`leadNo` 与 `customerIdentityKey` 同值、`syncGroupCode` 非空；`name`（标题）= company（带了公司时）
  3. 若带 `company`：`companyId` 非空，company 表有对应公司

### TC-WF-02 手动推进 stage（未处理线索 → 有效线索）
- **前置**：TC-WF-01 的线索
- **步骤**：模拟销售在 CRM 改 stage（GraphQL `updateOpportunity`，`stage = YOUXIAO_XIANSUO`）
- **预期**：DB `opportunity.stage = YOUXIAO_XIANSUO`；改 stage 不触发转客户/转项目（仍无 Person/项目）

### TC-WF-03 未填「客户需求产品」直接转客户 → 409
- **前置**：TC-WF-01 的线索（`keHuXuQiuChanPin` 为空）
- **步骤**：调 `convert-to-person`
- **预期**：返回 409，`code = PRODUCT_REQUIRED`；不生成 Person

### TC-WF-04 填产品后转客户 → 生成客户 + 回填关系
- **前置**：线索已填 `keHuXuQiuChanPin`
- **步骤**：调 `convert-to-person`
- **预期**：
  1. 返回 201，`personId` 非空、`created=true`
  2. DB：`person.nameFirstName = lianXiRenXingMing`（官网联系人姓名）；`person.leadNo = 线索 leadNo`；`opportunity.pointOfContactId = person.id`、`linkedPersonId = person.id`

### TC-WF-05 转项目 → 生成项目 + 三表线索id同源
- **前置**：TC-WF-04 已转客户（或直接带产品）
- **步骤**：调 `convert-to-project`
- **预期**：
  1. 返回 201，`projectId` 非空、`created=true`
  2. DB：`_xiangMu.leadNo = 线索 leadNo`；`opportunity.linkedProjectId = project.id`；`person.linkedProjectId = project.id`

### TC-WF-06 幂等：重复转客户/转项目不重复建
- **前置**：TC-WF-04/05 已执行过
- **步骤**：再次调 `convert-to-person`、`convert-to-project`
- **预期**：返回 200、`created=false`；DB 中 person/_xiangMu 记录数不变（仍各 1 条）

## 4. 链路 2 测试用例（WhatsApp）

### TC-WA-01 入站消息 → 自动落库 + 自动建线索

  1. 返回 200（`updated=true`，因已自动建）

## 6. 权限与沟通状态测试用例（2026-08-19 补充）

### TC-RBAC-01 普通销售只能看自己的 WhatsApp 会话
- **前置**：销售 A、销售 B 分别绑定不同 WhatsApp session。
- **步骤**：销售 A 登录对话工作台，切到 WhatsApp 渠道。
- **预期**：只看到 A 自己绑定 session 的会话；看不到 B 的 WhatsApp 会话；即使 URL 手动访问 B 的会话消息接口也应返回 403/不可见。

### TC-RBAC-02 管理员 / boss 在 WhatsApp 工作台也不跨个人号
- **前置**：管理员或 boss 没有绑定某销售 WhatsApp session。
- **步骤**：管理员 / boss 打开对话工作台 WhatsApp 渠道。
- **预期**：WhatsApp 仍按个人号隔离；不显示其他销售个人 WhatsApp 会话。

### TC-RBAC-03 销售主管 / boss 在沟通状态可看全部
- **前置**：存在多个销售的官网/WhatsApp/邮件会话，且已生成沟通状态记录。
- **步骤**：销售主管或 boss 打开「沟通状态」对象，点击「查看对话内容」。
- **预期**：可看到全部沟通状态记录；详情弹窗内可查看完整消息文本和附件链接；boss 仍不能发送消息或接管。

### TC-RBAC-04 负责人 / 协办人 / 协办人2 可见性
- **前置**：同一线索关联客户/项目，分别设置负责人、协办人、协办人2。
- **步骤**：对应成员登录对话工作台和沟通状态。
- **预期**：只要成员在三维度任一关联记录上是负责人/协办人/协办人2，即可看到该客户相关会话；无关成员不可见。
