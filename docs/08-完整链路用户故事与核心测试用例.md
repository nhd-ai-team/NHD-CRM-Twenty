# CRM 完整链路用户故事与核心测试用例

更新时间：2026-08-05

## 1. 范围说明

本文只覆盖当前 CRM 项目的完整业务链路，不展开通用 CRM 功能，也不把待办能力写成已交付能力。

当前 1.0 核心链路为：

官网表单 / 官网客服 / WhatsApp / 邮箱归档 -> CRM 对话工作台或邮件视图 -> 线索（Opportunities）-> 客户（People）-> 项目 -> 三表关联与同步。

当前不纳入 1.0 完整链路验收的内容：

- Instagram / Facebook 正式消息接入：已预留渠道，Meta 账号与权限仍需继续确认。
- LinkedIn：个人账号限制下暂不接入。
- 沟通状态全文搜索：作为后续独立模块，不与对话工作台混合。
- 复杂 AI 策略配置：知识库范围、允许回答类型、敏感词、话术库等后续放到设置中的 AI 配置。

## 2. 完整链路用户故事

作为海外销售人员，我希望客户从官网表单、官网客服和 WhatsApp 进入后，CRM 能自动沉淀客户信息、聊天记录和附件；当客户消息进入时，如果该渠道开启了 AI 自动回复且处于配置时间段内，AI 可以先根据知识库回复，无法回答时使用配置的兜底话术；当我需要人工处理时，必须先点击接管会话，确认后 AI 停止回复，我可以在 CRM 中直接发送文字和附件。WhatsApp 发送前必须确认当前 CRM 登录用户已绑定该 WhatsApp ID。

作为销售人员，我希望在 CRM 对话工作台中输入带国家区号的 WhatsApp 号码和首条消息，确认后主动发起一对一会话。系统必须先确认 WhatsApp 在线、号码已注册且不是当前绑定号码；号码已有历史会话时复用原会话，不重复创建。主动发送后会话进入人工接管状态，发送记录和当前操作用户可追溯。

作为销售人员，我希望在对话工作台右侧补充客户资料，并将会话写入或更新为线索。线索进入 Opportunities 后，系统生成隐藏业务编码 `syncGroupCode`，用于后续关联客户和项目。线索转客户前必须确认客户需求产品已填写；转客户时系统应按邮箱、电话、WhatsApp 或关联编码查重，优先更新已有客户，避免重复建档。

作为销售人员，我希望在线索表勾选已确认立项的线索后，一键转为项目。系统必须先校验客户需求产品，随后自动补齐客户关联、生成或复用项目，并通过 `syncGroupCode` 保持线索、客户、项目三表一致。

作为销售负责人或管理者，我希望线索、客户、项目之间保持一致：同一条业务链路在三张表中通过 `syncGroupCode` 关联，任一表更新共享字段后，其他表的对应记录能够同步更新，保证周会和日常跟进看到的是同一份业务事实。

## 3. 核心验收口径

P0 验收必须同时满足：

- 官网表单创建的线索自动带有客户来源=官网表单、任务进度=未处理线索。
- 官网表单重复提交按邮箱 / 电话识别；主线索核心字段不被最新提交覆盖，只补齐空字段，同时记录提交次数、首次 / 最近提交时间、最新表单快照和完整提交历史。
- 官网客服消息进入对话工作台，并在客户首条入站时自动创建线索；AI 开关与时间段生效；人工接管后 AI 停止自动回复。
- 官网客服和 WhatsApp 消息进入对话工作台，并在客户首条入站时自动创建线索，线索阶段默认为“线索”；人工接管后可发送文字和附件，附件名称正常显示；WhatsApp 未绑定到当前登录用户时禁止外发。
- 销售可主动新建 WhatsApp 会话；必须二次确认、验证号码、复用已有会话并防止重复提交造成重复发送。
- 设置 -> 账户 -> 渠道支持 WhatsApp 连接状态查看、绑定到当前 CRM 账号、解绑；同一个 WhatsApp ID 同一时间只能绑定一个 CRM 账号。
- 对话工作台右侧资料可以更新线索；姓名、公司非必填；填写 WhatsApp 或邮箱任意一个时，普通渠道线索阶段自动变为有效线索。
- 线索转客户有二次确认；缺少客户需求产品时阻断，并给出清晰失败原因。
- 线索转项目有二次确认；缺少客户需求产品时阻断；成功后自动补齐客户关联并创建或更新项目。
- 线索、客户、项目通过 `syncGroupCode` 关联；共享字段更新后能同步。
- 邮箱通过 IMAP 同步后，在 CRM 邮件入口可查看归档邮件。
- 主菜单符合当前业务顺序：对话工作台、邮箱、线索、客户、项目、沟通状态、设置。
- 沟通状态用于查看真实会话内容，数据源为 `conv.conversations` 和 `conv.messages`；审计事件仅用于追踪“谁在什么时候做了什么操作”，不能替代聊天记录。

### 4.3 编码规则

`syncGroupCode` 当前隐藏，不向销售前端展示。编码格式为 `NHD + YYYYMMDD + 当日自增流水号`，例如 `NHD20260731001`。流水只递增，不因删除历史数据而回收编号。

### 4.4 官网表单重复提交规则

官网表单是客户输入的原始事实流，线索主记录是销售确认后的业务判断，两者不互相覆盖。官网表单重复提交按邮箱 / 电话 / WhatsApp 号码识别。首次提交正常创建主线索；重复提交命中主线索后，不创建新的可见线索，重复插入行软删除。主线索只补齐空字段，不覆盖已有非空核心字段；同时维护 `websiteFormSubmissionCount`、`websiteFormFirstSubmittedAt`、`websiteFormLastSubmittedAt`、`websiteFormLatestSnapshot`。每次提交的原始内容完整写入 `conv.website_form_submissions`，用于后续审计、查看提交历史和销售判断。

| TC-044 | P1 | 发送成功但归档异常 | 模拟 WhatsApp 发送成功后数据库临时失败 | 使用同一请求再次提交 | 系统提示消息已发出且正在归档，不再次向客户发送；异常可追踪并人工修复 |
| TC-046 | P0 | WhatsApp 账号绑定 | WhatsApp 已连接但 CRM 未绑定 | 当前用户点击“绑定到我的账号” | `conv.channel_accounts` 写入当前用户与 WhatsApp ID 的绑定；状态显示“已绑定到我的账号” |
| TC-047 | P0 | WhatsApp 唯一绑定 | 同一 WhatsApp ID 已绑定到用户 A | 用户 B 打开渠道设置并尝试绑定或发送 | 系统提示已绑定到其他用户；用户 B 不能使用该 WhatsApp ID 发送 |
| TC-048 | P0 | WhatsApp 解绑 | 当前用户已绑定 WhatsApp | 点击解绑并二次确认 | CRM 绑定状态变为未绑定；WAHA session 断开；后续需重新扫码/配对并绑定后才能发送 |
| TC-049 | P0 | 线索转项目按钮 | 线索表勾选一条线索，且客户需求产品已填 | 点击转项目，确认执行 | 项目创建或更新成功；系统自动补齐 People 关联；Opportunity 回写 `linkedPersonId` / `linkedProjectId`；三表使用同一 `syncGroupCode` |
| TC-050 | P0 | 转项目幂等 | 同一线索已经转过项目 | 再次点击转项目并确认 | 更新已有项目，不重复创建项目；`syncGroupCode` 和关联关系保持不变 |
| TC-051 | P0 | 转项目必填校验 | 勾选的线索缺少客户需求产品 | 点击转项目并确认 | 阻断转项目；失败原因清晰指出需填写客户需求产品 |

## 6. 建议回归顺序

每次主链路发布前按以下顺序回归：

1. 官网表单 -> 线索默认字段 -> 编码生成。
2. 官网客服 -> AI 时间段 -> 人工接管 -> 人工回复。
3. 官网客服 -> 接管 -> 文字发送 -> 附件发送。
4. WhatsApp -> 入站 -> 接管 -> 文字发送 -> 附件发送 -> 主动新建 -> 重复会话复用。
5. 对话工作台右侧资料 -> 更新线索 -> 公司复用 / 新建。
6. 线索表 -> 转客户 -> 查重 -> 字段映射。
7. 线索表 -> 转项目 -> 自动补齐客户 -> 项目字段映射。
8. 线索、客户、项目任一表更新 -> 其他表同步。
9. 邮箱 IMAP -> 邮件视图归档。
10. 主菜单、入口、缓存刷新后的可见性。

## 7. 发布阻断标准

以下任一问题未解决，不建议上线：

- 官网表单不能稳定创建线索，或默认客户来源 / 任务进度错误。
- 官网客服或 WhatsApp 消息不能进入 CRM。
- AI 在关闭或非生效时间段仍自动回复。
- 人工接管后 AI 仍继续回复。
- 官网客服或 WhatsApp 文字 / 附件无法发送。
- 转客户会重复创建客户，或缺少客户需求产品时仍允许转客户。
- 转项目会重复创建项目，或缺少客户需求产品时仍允许转项目。
- 三表同步导致字段丢失、覆盖错误或循环更新异常。
- `syncGroupCode` 重复、为空或流水回收。

## 8. 2026-08-05 端到端审查结果

本轮按“官网访客 / 表单 -> CRM 线索 -> 客户 -> 项目 -> 三表同步”和“官网会话 -> AI / 人工接管 -> 附件发送”主链路执行实测。

### 已跑通

| 链路 | 结果 |
| --- | --- |
| 官网访客通过官网消息接口发送消息 | AI 服务接收成功，并转发到 CRM 对话工作台；CRM 生成 website 会话和客户消息 |
| 官网 AI 自动回复 | CRM 根据渠道 AI 开关和托管窗口调用 AI 服务；知识未命中时返回统一兜底话术，并写入同一会话 |
| 人工接管 / 释放 AI 托管 | 接管后会话状态变为 takeover；释放后状态回 open；释放后新访客消息再次触发 AI 回复 |
| 官网客服人工文字回复 | 接管后可从 CRM 发送文字，AI 服务返回 messageId，CRM 消息表落库为 agent 消息 |
| 官网客服附件发送 | 接管后可发送 PDF 类附件；CRM 保存 mediaUrl 和 attachments 元数据 |
| 对话转线索 | 官网会话可写入 Opportunity；当前 Opportunity 缺失的公司类型字段会跳过，不再阻断创建 |
| 线索编码 | Opportunity 自动生成 `syncGroupCode`，格式为 `NHDYYYYMMDDNNN` |
| 线索转客户 | 已验证 Opportunity 可转 People；People 回写 `sourceOpportunityId`，Opportunity 回写 `linkedPersonId` |
| 线索 / 客户同步 | 更新 Opportunity 的客户需求产品会同步到 People；更新 People 的国家会同步回 Opportunity |
