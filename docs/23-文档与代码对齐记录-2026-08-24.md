# 23 · 文档与代码对齐记录（2026-08-24）

> 本记录用于说明 2026-08-24 针对「官网会话地址信息、IP、UTM 来源信息在对话工作台不显示」问题的代码修复和文档同步口径。

---

## 1. 本次问题

用户反馈：对话工作台中官网会话原本可以展示访客地址信息、UTM 等来源信息，但当前不再显示。

排查结论：

- 对话工作台前端仍有地域展示逻辑，不是单纯 UI 被删。
- 最新官网会话进入 `conv.contacts` 时，很多记录只保存了容器内网 IP，例如 `172.18.0.11`。
- 内网 IP 不能代表访客位置，也不会触发有效 GeoIP 解析。
- CRM 中间层原来没有 `landing_page_url`、`referrer_url`、`utm_*` 字段，因此即使官网 widget 传了页面来源，也没有沉淀到 CRM。
- 默认 GeoIP provider `ip-api` 的调用格式已修正为 `/json/<ip>`，避免解析成服务器出口位置。

---

## 2. 当前实现口径

官网 Widget 客户消息链路：

```text
官网 widget
  -> ai-service /api/website-channel/messages
  -> ai-service forward_to_crm()
  -> middleware /api/website/webhook
  -> conv.contacts + conv.conversations + conv.messages
  -> chat-ui 对话工作台展示
```

当前 `ai-service` 转发到 CRM 时会携带：

- `clientIp` / `x-original-client-ip`
- `pageUrl`
- `referrer`
- 附件元数据

当前 `middleware` 会在 `conv.contacts` 中沉淀：

| 字段 | 用途 |
|---|---|
| `ip_address` | 官网访客公网 IP，仅用于审计和地域推断 |
| `geo_country_code` | 国家代码 |
| `geo_country_name` | 国家名称 |
| `geo_region` | 省 / 州 / 地区 |
| `geo_city` | 城市 |
| `geo_timezone` | 时区 |
| `geo_latitude` / `geo_longitude` | 经纬度 |
| `geo_source` | GeoIP 来源，例如 `ip-api` |
| `landing_page_url` | 访客发起会话时所在页面 URL |
| `referrer_url` | 来源页 / referrer |
| `utm_source` | UTM source |
| `utm_medium` | UTM medium |
| `utm_campaign` | UTM campaign |
| `utm_term` | UTM term |
| `utm_content` | UTM content |

当前对话工作台展示：

- 会话顶部详情：国家 / 地区 / 城市 / 时区 / IP / Geo 来源。
- 会话顶部详情：UTM、访问页、来源页；内容过长时单行省略，鼠标悬停可看完整内容。
- 官网会话列表：展示简短地域；若有 UTM source 或 campaign，会追加展示来源摘要。

## 3. 安全与边界

- 真实访客 IP 只从可信链路取：`CF-Connecting-IP`、`X-Forwarded-For`、`X-Real-IP`、`x-original-client-ip`。
- `clientIp` 请求体字段只在 `/api/website/webhook` 已通过内部密钥校验后作为兜底使用。
- 私网 / 回环 / 容器网段 IP 不入库，不做 GeoIP 解析。
- 历史记录如果当时只保存了 `172.18.0.11` 等内网 IP，无法反推出真实访客位置，不能回填。
- WhatsApp 和 email 不展示伪造地域。只有官网客服这类有 Web 访问上下文的渠道展示 IP / UTM。
