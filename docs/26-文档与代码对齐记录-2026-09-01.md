# 文档与代码对齐记录：2026-09-01 官网访客地区信息恢复

## 1. 问题现象

2026-08-31 最近 4 条官网 Widget 会话已经保存公网 IP，但工作台没有显示国家、地区、城市和时区。

## 2. 根因

官网消息入站链路和数据库写入正常，问题发生在 middleware 的 IP 地理解析环节：

- `conv.contacts.ip_address` 已保存真实公网 IP；
- middleware 调用 `ip-api.com` 时，Docker 默认上游 DNS 不可用，Node 返回 `EAI_AGAIN`；
- 地理解析失败按设计不会阻断消息入库，因此 `geo_*` 字段保持为空；
- 这不是 Widget 字段丢失，也不是工作台前端渲染问题。

## 3. 修复内容

`docker-compose.yml` 为 middleware 持久化配置局域网 DNS：

```yaml
dns:
  - ${DOCKER_DNS_SERVER:-192.168.118.1}
```

该值支持通过 `DOCKER_DNS_SERVER` 覆盖。重建 middleware 容器后，DNS 和 GeoIP 请求均已恢复。

## 4. 数据补偿

仅对以下范围执行补偿：

- `channel = 'website'`；
- 已存在公网 IP；
- `geo_source IS NULL`；
- `updated_at >= 2026-08-31 00:00:00+08`。

共扫描并更新 4 条记录，写入国家、地区、城市、时区、经纬度和 `geo_source = 'ip-api'`。未对更早记录进行猜测性回填。

## 5. 验证结果

- 容器内 `ip-api.com` DNS 解析成功；
- GeoIP 请求返回 HTTP 200；
- middleware `/health` 返回 `status: ok`；
- 最近 4 条官网会话均已返回地区信息；
- 新消息仍沿用 `middleware/index.js` 的真实 IP 提取、24 小时缓存和失败不阻断入库逻辑。

## 6. 运维边界

IP 地理位置是网络归属推断，不是 GPS 精确定位。Mac mini 更换网络或局域网 DNS 后，应检查 `DOCKER_DNS_SERVER` 是否仍可达，并验证：

```bash
docker exec twenty-middleware-1 node -e 'require("dns").lookup("ip-api.com", console.log)'
curl http://127.0.0.1:3002/health
```
