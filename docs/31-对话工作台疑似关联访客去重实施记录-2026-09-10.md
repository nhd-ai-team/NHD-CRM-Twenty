# 31 · 对话工作台疑似关联访客去重实施记录

最后更新：2026-09-10

## 1. 需求边界

当官网访客尚未填写邮箱、电话或 WhatsApp 时，如果多个官网客服会话来自同一真实公网 IP，工作台需要提示销售可能是同一客户或关联人员。该能力只做提醒，不自动合并会话，不覆盖负责人，不修改历史消息。

## 2. 实现方案

- `middleware /api/conversations` 仅对 `website` 会话计算关联访客。
- 匹配条件为 `conv.contacts.ip_address` 与当前会话相同，排除当前会话，最多返回 10 条。
- 返回会话 ID、访客名称、最后消息时间和访问页，前端不直接暴露数据库结构。
- 当前会话头部的“疑似关联访客”可展开，点击后按会话 ID补加载并定位目标会话，解决目标会话不在首批 30 条时无法打开的问题。
- 左侧会话列表的提示为展示-only，不提供跳转，避免列表点击区域与会话选择冲突。

## 3. 对抗性检查

| 场景 | 预期 |
|---|---|
| 同公网 IP 的两条官网会话 | 显示疑似关联提示 |
| 当前会话自己 | 不出现在关联列表 |
| WhatsApp / 邮箱会话 | 不按 IP 关联，不误报 |
| 私网、回环、容器 IP | 不作为可靠匹配依据 |
| 关联目标不在首批 30 条 | 点击后按 ID补加载并打开 |
| 关联会话已被删除或无权限 | 不崩溃，提示或忽略无效项 |
| 重复刷新/重复点击 | 不创建新会话，不修改历史消息 |
