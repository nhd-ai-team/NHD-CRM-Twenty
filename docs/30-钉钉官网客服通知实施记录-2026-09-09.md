# 30 · 钉钉官网客服通知实施记录（2026-09-09）

## 1. 需求结论

官网客服收到新访客或新消息时，通过钉钉内部应用向销售发送单向工作通知：

- 未分配负责人时，每条官网客户消息通知配置的默认销售账号。
- 已分配负责人时，按 CRM 负责人的登录邮箱查找钉钉 UserId；协办人和协办人2也纳入收件人。
- 会话进入人工接管后，只通知当前接管人。
- 不使用群机器人，不发送 CRM 反向消息。

## 2. 技术实现

middleware 使用钉钉旧版企业内部应用消息接口获取 access token，并调用 `topapi/message/corpconversation/asyncsend_v2` 发送 markdown 工作通知。

官网客户消息入库成功后，先写入 `conv.dingtalk_notification_outbox`，由后台 worker 每 5 秒扫描待发送记录。表约束 `(event_key, recipient_user_id)` 唯一，防止同一事件重复通知；发送失败最多重试 5 次，最终保留 `failed` 和 `last_error`。

关键配置（仅存在本地 `.env`，禁止提交密钥）：

```text
DINGTALK_ENABLED=true
DINGTALK_APP_KEY=<internal-app-key>
DINGTALK_APP_SECRET=<internal-app-secret>
DINGTALK_AGENT_ID=<agent-id>
DINGTALK_SALES_USER_IDS=<optional-comma-separated-direct-dingtalk-userids>
DINGTALK_SALES_USER_EMAILS=<comma-separated-crm-login-emails>
DINGTALK_USER_MAP_JSON={"crm-login-email":"dingtalk-userid"}
```

## 3. 应用边界

同一个钉钉应用的工作通知会进入钉钉统一的工作通知窗口；新建另一个内部应用只能区分应用身份，不能保证生成独立窗口。服务窗单聊需要客户端 `requestAuthInfo` 授权和另一条发送链路，目前仅记录为后续方案，不影响当前工作通知。
