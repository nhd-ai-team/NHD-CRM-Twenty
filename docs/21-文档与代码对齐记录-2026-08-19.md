### 1.3 统一路由解析

- `parseRoute()` + `canonicalObject()`（00-head.js）：单一事实源，兼容单数/复数 `/object(s)/<slug>/<uuid>`，`OBJECT_SLUGS` 归一 slug（duiHuaLiShis→duiHuaLiShi 等）。
- 消灭散落 5 处的正则：`findDuiHuaLiShiRecordId` / `collaboratorRecordContext` / `opportunityRecordId` / `isOpportunityListPage` 等全部改走统一函数。
- **坑**：Twenty v2 详情页真实路由是 **单数 `/object/<slug>/<uuid>`**（列表页才是 `/objects/<slug>s`），所有匹配必须兼容 `/objects?/`。

### 1.4 沟通明细内联文本弹窗（20-drill.js）

- 用户诉求：钻取不应整页跳转到聊天视图（切页后上下文丢失、难以快速定位），应就地以文本形式直接呈现。
- 实现：`openConversationTextModal(cid)`：fetch `GET /conv-api/conversations/:id/messages`（带 `getTwentyAuthHeaders`）按时间正序渲染消息（senderType→客户蓝/我方紫/AI 绿标签 + 时间 + content pre-wrap + mediaUrl/attachments 附件链接），顶部关键词过滤框即时定位，底部保留「在完整对话页打开」可选入口（showView）。conversationId 缺失/未找到时弹窗内提示，不跳转。
- 消息 API 字段：`{id, senderType(customer|agent|ai), content, contentType, mediaUrl, subject, attachments(JSONB), sentAt, deliveryStatus...}`；鉴权 `X-Twenty-Access-Token`。

### 1.5 钻取按钮残留修复（inline-chat-v2）

- 现象：退出「沟通状态」详情后到「对话工作台」（打开"资料"抽屉），右下角「查看对话内容」按钮仍在。
- 根因：`findDuiHuaLiShiRecordId` 的 **S3 兜底**——「抽屉内任意 `/object` 锚点」误命中资料抽屉里的 person/线索/客户/项目链接，把它们的 uuid 当成 duiHuaLiShi id → `recordId` 非空 → 按钮不清理。
- 修复：删除 S3 兜底。S2 已严格只匹配 `a[href*="/object/duiHuaLiShi"]`，真实 duiHuaLiShi 抽屉详情场景下「在完整页面打开」自链接必然存在，够用。
- **铁律**：注入脚本的"兜底识别"逻辑严禁用宽泛选择器（如 `a[href*="/object/"]`）作 fallback 命中其他对象的 uuid——会让"离开上下文后按钮不清理"在所有非目标页面必现。

### 1.7 线索页崩溃「抱歉，出了点问题」排查（v5/v6）

- 现象：线索（opportunity）页出现 Twenty 错误边界「抱歉，出了点问题」；服务端日志全干净 → 浏览器端 JS 崩溃（nginx 错误页背景图 referer=`/objects/opportunities` 佐证）。
- **根因（两层）**：① `applyLeadCompanyUiFix` 的 MutationObserver(characterData) 回调内**同步改 DOM**（textContent/style/setAttribute）——observer 回调在 React commit 间隙触发，打断协调器；② 更深一层：`scheduleTick()` 节流命中时**同步调用 tick()**，而 tick 内所有 ensure*（导航注入、隐藏原生导航、转客户按钮等）都改 React 节点——这是所有注入共用的风险路径。
- **修复**：① applyLeadCompanyUiFix 改「收集变化子树 + 120ms 防抖异步」（v5）；② scheduleTick 命中节流分支改为 `setTimeout(function(){tick()},0)`——**tick 永远异步执行**，所有 DOM 修改天然与 React commit 错开（v6）。
- **铁律（写入技能）**：注入脚本 DOM 修改必须与 React 渲染完全错开——tick 必须异步；MutationObserver 回调严禁同步改 DOM；只扫变化子树不全文档扫。

### 1.8 浏览器端错误诊断与沟通状态负责人关系（v7）

- **注入层错误诊断**：`nginx/inject/src/00-head.js` 增加全局 `error` / `unhandledrejection` 捕获，最近 80 条记录保存在 `window.__NHD_ERRORS__`，字段包含错误类型、消息、文件、行列、堆栈、时间与当前 URL。用途是排查「设置页/对话工作台/线索页空白但服务端日志正常」这类浏览器端问题。
- **版本口径**：`nginx/twenty-portal.conf` 注入缓存版本为 `chat-nav.js?v=20260819-inline-chat-v7`；脚本运行态 `window.__NHD_VERSION__` 为 `20260819-inline-chat-v6`，表示当前逻辑基线仍沿用 v6，仅增加诊断能力与缓存刷新。
- **沟通状态负责人写入**：`middleware/index.js#buildHistoryPayload()` 查询 workspace schema 下的 `workspaceMember`，把 `conv.conversations.owner_id`（userId）转换为 `workspaceMember.id` 后写入 `ownerMemberId`。原因是沟通状态对象的负责人字段是 RELATION→workspaceMember，不能直接写 userId；找不到对应 workspaceMember 时留空，避免写入失败。
