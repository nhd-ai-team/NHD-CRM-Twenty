### 1.3 统一路由解析

- `parseRoute()` + `canonicalObject()`（00-head.js）：单一事实源，兼容单数/复数 `/object(s)/<slug>/<uuid>`，`OBJECT_SLUGS` 归一 slug（duiHuaLiShis→duiHuaLiShi 等）。
- 消灭散落 5 处的正则：`findDuiHuaLiShiRecordId` / `collaboratorRecordContext` / `opportunityRecordId` / `isOpportunityListPage` 等全部改走统一函数。
- **坑**：Twenty v2 详情页真实路由是 **单数 `/object/<slug>/<uuid>`**（列表页才是 `/objects/<slug>s`），所有匹配必须兼容 `/objects?/`。

### 1.4 沟通明细内联文本弹窗（20-drill.js）

- 用户诉求：钻取不应整页跳转到聊天视图（切页后上下文丢失、难以快速定位），应就地以文本形式直接呈现。
- 实现：`openConversationTextModal(cid)`：fetch `GET /conv-api/conversations/:id/messages`（带 `getTwentyAuthHeaders`）按时间正序渲染消息（senderType→客户蓝/我方紫/AI 绿标签 + 时间 + content pre-wrap + mediaUrl/attachments 附件链接），顶部关键词过滤框即时定位，底部保留「在完整对话页打开」可选入口（showView）。conversationId 缺失/未找到时弹窗内提示，不跳转。
- 消息 API 字段：`{id, senderType(customer|agent|ai), content, contentType, mediaUrl, subject, attachments(JSONB), sentAt, deliveryStatus...}`；鉴权 `X-Twenty-Access-Token`。

### 1.5 钻取按钮残留修复（inline-chat-v2）

- 现象：退出「沟通状态」详情后到「对话工作台」（打开"资料"抽屉），右下角「查看对话内容」按钮仍在。
- 根因：`findDuiHuaLiShiRecordId` 的 **S3 兜底**——「抽屉内任意 `/object` 锚点」误命中资料抽屉里的 person/线索/客户/项目链接，把它们的 uuid 当成 duiHuaLiShi id → `recordId` 非空 → 按钮不清理。
- 修复：删除 S3 兜底。S2 已严格只匹配 `a[href*="/object/duiHuaLiShi"]`，真实 duiHuaLiShi 抽屉详情场景下「在完整页面打开」自链接必然存在，够用。
- **铁律**：注入脚本的"兜底识别"逻辑严禁用宽泛选择器（如 `a[href*="/object/"]`）作 fallback 命中其他对象的 uuid——会让"离开上下文后按钮不清理"在所有非目标页面必现。
