## 2. 核心技术方案

### 2.1 请求链路

```
浏览器 / 官网 / WhatsApp
  -> Cloudflare Tunnel / crm.chinanhd.com
  -> twenty-portal nginx
     -> Twenty 原生页面与 GraphQL
     -> /conv-api/* 转发到 middleware
     -> /chat/ 转发到 chat-ui
  -> PostgreSQL + Redis
```

### 2.2 三类数据存储

| 数据类型 | 存储位置 | 说明 |
|---|---|---|
| CRM 结构化业务数据 | Twenty workspace schema：`workspace_3zyju8y4v9gnoifvksi4cn23f` | 线索、客户、项目、公司、字段元数据、视图配置 |
| 会话与渠道数据 | `conv` schema | conversations、messages、contacts、channel_accounts、roles、audit、website_form_submissions |
| 附件文件 | middleware 本地上传目录，对外通过 `/conv-api/uploads/conversation-files/*` 访问 | 会话消息只保存附件元数据和 URL |

### 2.3 权限模型

| 场景 | 当前规则 |
|---|---|
| WhatsApp 工作台 | 不管 admin / boss / sales，个人 WhatsApp 会话只看自己绑定账号相关的会话 |
| 官网客服工作台 | open 公共会话可见；接管后按负责人、参与人、线索/客户/项目负责人或协办人可见 |
| 沟通状态 | `allowPrivilegedAllChannels` 场景下管理员 / boss / 销售主管可看全部沟通记录；普通销售仍按本人相关数据看 |
| boss | 仅查看，不允许发送消息、接管、改分配 |
| 协办人 | `xieBanRenId` 和 `xieZuoRen2Id` 纳入会话可见性判断 |

## 5. 需要继续稳定测试的点

| 测试项 | 重点 |
|---|---|
| 设置页渠道绑定 | 进入 `/settings/profile#channels` 不应让左侧设置菜单消失；刷新后不会长时间卡死 |
| 工作台加载 | 切换对话工作台 / 线索 / 客户 / 设置后，左侧主菜单不应退回旧对象顺序或缺项 |
| React 错误边界 | 大表格页、线索页、设置页切换过程中不应出现「抱歉，出了点问题」；注入层 MutationObserver 不允许同步改 React DOM |
| WhatsApp 绑定 | 绑定、解绑、重新生成二维码/配对码、掉线后的状态提示 |
| 线索转客户/项目 | 未填产品失败弹窗原因清晰；已填产品后客户/项目不重复创建 |
| 三维度同步 | 修改 owner / 协办人 / WhatsApp / 邮箱 / 国家 / 官网链接 / 最新跟进后，同 `syncGroupCode` 数据同步 |
| 权限隔离 | 普通销售只看到自己的 WhatsApp 和自己相关数据；销售主管 / boss 在沟通状态可看全部 |
